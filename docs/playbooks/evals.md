# Эвалы

Проверено: 2026-11-14.

Эвал — это тест для ИИ-части. Обычные тесты не замечают, что модель стала отвечать хуже после правки промпта.

## Как устроено

- Случаи лежат в `ml/evals/cases.jsonl`, по одному JSON на строку.
- `make eval` шлёт запросы в запущенный сервис `ml`, печатает результат и сохраняет его в `ml/evals/results/` с хэшем коммита. Если случай проходил в прошлом прогоне, а теперь упал, он помечается как регрессия.

## Типы проверок

| type | Что проверяет | Когда брать |
| --- | --- | --- |
| `code` | Поле ответа равно значению или содержит подстроку | Всегда, когда ответ можно проверить кодом |
| `tool` | Агент вызвал нужный инструмент | Агенты и MCP |
| `judge` | Модель-судья оценивает ответ по рубрике | Только когда кодом не проверить |

Судья вызывает модель через `ml/app/llm/client.py` с промптом из `ml/prompts/judge.md` и ждёт ответ `{"pass": true/false, "reason": "..."}`. Если в `ml/.env` не заданы `LLM_MODEL` и `ANTHROPIC_API_KEY`, такие случаи помечаются `SKIP`.

## Правила

- До кода ИИ-части записать 5–10 случаев по сценарию демо из брифа.
- Каждый найденный плохой ответ модели становится новым случаем.
- Сначала проверка кодом, судья в последнюю очередь: он дороже и сам ошибается.
