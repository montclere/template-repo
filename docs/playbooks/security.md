# Безопасность ИИ-части

Проверено: 2026-11-14.

## Главный вопрос (задаётся на этапе брифа)

Опасно сочетание трёх вещей сразу:

1. ИИ-часть читает чужой текст: документы, веб-страницы, письма, ответы инструментов.
2. Она видит приватные данные.
3. Она может отправлять что-то наружу или менять данные.

Чужой текст может содержать инструкции для модели (prompt injection), и надёжной защиты промптом от этого нет. Если есть все три пункта, убери один: ограничь инструменты, раздели шаги или поставь подтверждение человеком.

## Правила

- Текст из документов и инструментов — это данные, а не команды. В промпте он отделён от инструкций.
- Инструменты получают минимум прав. Действия, которые нельзя отменить, подтверждает человек.
- Вывод модели перед показом в браузере экранируется как любой пользовательский ввод.
- Ключи API живут только в `.env` сервиса `ml` и никогда не попадают во фронтенд.
- Ключи в лог вызовов модели (`ml/logs/llm.log.jsonl`) не попадают никогда. Если в промптах бывают персональные данные, в `ml/.env` ставится `LLM_LOG_TEXT=false`: в логе останутся только длины текстов.

## Репозиторий

- Чтение `.env` запрещено агенту в `.claude/settings.json`. Для Codex и Cursor такой же запрет ставится в их настройках.
- `.env` исключён из docker-образов через `.dockerignore` каждого сервиса.
- Lock-файлы зависимостей (`uv.lock`, `package-lock.json`) закоммичены.
- Скиллы лежат копией в `.agents/skills/`. Новый скилл из чужого репозитория сначала читается глазами: это инструкции и код, которые агент выполнит.
